# Systematic review: organisational capacity in community sport clubs

| File | What it is |
|---|---|
| **`organised_extraction.xlsx`** | **Primary dataset.** Quantitative and mixed-methods sheets (Overview, Indicators, Limitations, Effect sizes each) and qualitative sheets (Overview, Limitations); papers keep the same ID throughout. Column headers carry codes (O1–O23, I1–I7, L1–L6) defined in `CODEBOOK.md` |
| `FINDINGS.md` | Key findings, insights, research gaps, and data points to check |
| `CODEBOOK.md` | What every column means, allowed values and decision rules, based on Hall et al.'s (2003) model. Paper checks cite these rules |
| `HIGHLIGHT_COLOURS.md` | Colour for each category of evidence in the highlighted PDFs (the tool reads this file) |
| `evidence/` | One evidence table per verified paper (`paper_XX.md`): every value with the quote and page it came from |
| `checklists/` | Blank checklist per paper, generated by the tool: every item by tag (e.g. `O15`), with dropdowns to record that you checked the highlight and whether you agree |
| `sinanverification/` | **Your completed checklists** (verdicts and notes), plus `verification_log.xlsx` (Change log and Verification record) |
| `highlighted/` | Highlighted copy of each checked paper (kept local; not committed) |
| `tools/evidence.py` | Builds the evidence table and the highlighted PDF from `evidence/paper_XX.csv` |
| `archive/` | Everything else: the raw extraction workbook, the Python pipeline that built the first organised version, its summary tables, figures, quality checks and review workflow. See `archive/README.md` |

Edit `organised_extraction.xlsx` directly from now on. The archived scripts read
the raw workbook in `archive/data/raw/`, not this file, so re-running them will not
pick up edits made here.

## Verifying a paper against its PDF

1. Put the paper in `papers/` (e.g. `papers/paper_01.pdf`). PDFs are never committed.
2. Record each piece of evidence in `evidence/paper_01.csv`: Tag (column code, e.g. `O12a`),
   Section, Field, Category (from `HIGHLIGHT_COLOURS.md`), Value, Suggested, Status
   (Matches / Suggest change / Decision needed), Basis (Stated / Inferred / Not found),
   Quote (exact words from the paper), Location, and Reasoning (citing the `CODEBOOK.md` rule).
3. Run:

   ```bash
   pip install -r tools/requirements.txt
   python tools/evidence.py papers/paper_01.pdf evidence/paper_01.csv
   ```

   This writes `checklists/paper_01_checklist.xlsx` (tick off each tag), `evidence/paper_01.md`
   (the page each quote was found on), and
   `highlighted/paper_01_highlighted.pdf`. Each quote is highlighted in its category
   colour, with its tag in the margin and a wavy underline when the value is inferred. Clicking a highlight shows
   the reasoning, and the first page has a colour legend and an index of every field.
   A quote that isn't found in the PDF is marked ✗ and not highlighted.

4. Fill in the checklist (Highlight checked, Your verdict = Yes / No / Unsure, Your note)
   and save it to `sinanverification/paper_01_checklist.xlsx`. Then run:

   ```bash
   python tools/apply_checklist.py sinanverification/paper_01_checklist.xlsx
   ```

   Agreed suggestions are written to `organised_extraction.xlsx`. Every accepted or
   rejected suggestion goes to the **Change log**, and the paper gets a row in the
   **Verification** record, both in `sinanverification/verification_log.xlsx`. New decisions are added to the Decisions log in
   `CODEBOOK.md`.
